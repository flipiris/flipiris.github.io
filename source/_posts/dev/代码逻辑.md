这份文档说明站点从 Markdown / HTML 到页面，再经过模板、样式与浏览器脚本的完整链路。日常命令和字段见 [参考速查](reference.md)，使用入口见 [README](../README.md)。

# 1. 加载与生成周期

Hexo 启动时加载 `themes/iris-paper/scripts/` 下的脚本：

```text
content-blocks.js       正文处理、画布文档、预设校验
folder-categories.js    目录 → 分类关系
navigation-data.js      导航数据、最近更新、misc、分类/标签索引
site-stats.js           字数、阅读时间、站点统计、热力图
lib/documents.js        site.pages 中的内容页筛选（被上面几个脚本引用）
```

这些脚本通过 `hexo.extend.filter`、`helper`、`generator` 注册能力，不直接生成 HTML。生成顺序大致是：

1. Hexo 读取 `source/` 与 front matter，渲染 Markdown / HTML 正文。
2. `after_post_render` 把独占段落、带 `title` 的图片改成 `figure`。
3. `before_generate` 清空本轮缓存，并按目录重设每篇文章的分类。
4. 生成器产出首页、归档、分类、标签、更新、misc 等页面。
5. EJS 模板调用 helper 取导航、统计、注释、画布文档，拼出最终 HTML。
6. 主题 `source/` 下的 CSS、JS、字体和站点 `source/attachments/` 原样复制到 `public/`。

缓存都按“一次生成”失效：`before_generate` 清空注释解析、首页 Markdown、统计快照和字数缓存。预览连续修改时不会读到上一轮的数据。

# 2. 页面判定

`content-blocks.js` 的 `page_layout(page)` 只认三种值：

```text
article   默认文章
canvas    画布作品
page      独立页、首页、归档、分类、标签、misc、最近更新
```

`layout.ejs` 在模板开头计算：

- `canvas = layoutName === 'canvas'`
- `canvasDocument = canvas && /<html[\s>]/i.test(page.content || '')`
- `hasInfo = layoutName !== 'page'`

由此得到四种关键状态：

| 状态 | 条件 | 结果 |
| --- | --- | --- |
| article | `layout: article` | 700px 纸张、标题、信息窗、文章页脚 |
| page | `layout: page` 或索引布局 | 800px 无纸张、标题、无信息窗 |
| canvas prose | `layout: canvas` + Markdown 片段 | 800px 最简容器、信息窗、无标题/文章页脚 |
| canvas document | `layout: canvas` + 完整 HTML | 顶栏 + 全视窗 iframe + 站点页脚，信息窗从顶栏打开 |

`body` 上最终会带：

```html
<body data-layout="canvas" data-canvas="document" data-alignment="centered" data-palette="ink" data-typography="...">
```

`data-layout` 决定骨架，`data-canvas` 决定画布是完整文档还是片段，`data-alignment` 只影响 `page` 的居中方式，`data-palette` / `data-typography` 由 `page_style(page)` 校验后写入。

# 3. 模板链

```text
layout.ejs
├─ head          CSS 顺序、字体预加载、canonical、页面 styles
├─ body
│  ├─ skip-link
│  ├─ header     首页大标题 / 顶栏（完整 HTML 画布同样使用）
│  ├─ .site-layout
│  │  ├─ aside.site-rail   目录 + 全站信息 + 社交（完整 HTML 画布只保留固定目录触发器）
│  │  ├─ main
│  │  │  └─ article.ejs / page.ejs / canvas.ejs
│  │  │     └─ _partial/content-page.ejs
│  │  │        ├─ page-title
│  │  │        ├─ _partial/post-content.ejs
│  │  │        └─ _partial/article-footer.ejs
│  │  ├─ _partial/post-info.ejs   article / canvas（完整 HTML 画布从顶栏打开）
│  │  └─ footer.site-footer
│  └─ menu-backdrop               窄屏目录遮罩
```

`article.ejs`、`page.ejs`、`canvas.ejs` 都只是对 `content-page` 的薄封装：

- `article.ejs` 传 `contentTitle: page_layout(page) === 'canvas' ? false : page.title`，非 canvas 时打开文章页脚。
- `page.ejs` 从 `index.ejs`、`archive.ejs`、`misc.ejs` 等接收 `pageTitle` / `pageClass` / `pageBody`。
- `canvas.ejs` 直接复用 `article`，差异全部交给 `data-canvas` 与 CSS。

`post-content.ejs` 决定正文形态：

- 完整 HTML 画布：`canvas_document()` 返回文档字符串，渲染成 `<iframe class="canvas-document" srcdoc="...">`。
- 其他页面：`split_note()` 去掉注释块后，把 `parts.body` 直接放进 `.article-content`。

iframe 的 sandbox 是：

```text
allow-scripts allow-popups allow-popups-to-escape-sandbox
allow-top-navigation-by-user-activation allow-downloads
```

没有 `allow-same-origin`，作品脚本不能读取父页 DOM；通信只走 `postMessage`。

`post-info.ejs` 使用同一份 `page.content` 生成：

- `split_note()` 取注释内容，决定是否出现「信息 / 注释」页签。
- `toc()` 生成大纲。
- `page_stats()` 生成字数与阅读时间。
- `.read-progress` 两条进度条：顶栏一条、信息窗一条。

# 4. 正文处理

## 注释块

`split_note(content)` 用 `htmlparser2` 解析并保留 `startIndex` / `endIndex`：

1. 找顶层 `div.note`，嵌套的 `.note` 只算一次。
2. 取注释块内部的原始 HTML（保留实体和标签）。
3. 从正文中切掉这些块。
4. 多个注释块按出现顺序合并。

结果缓存到 `Map`，同一轮生成里同一篇正文只解析一次。

## 图注

`figureCaptions(content)` 只匹配“独占一段、带 `title` 的图片”：

```html
<p><img src="..." title="说明"></p>
```

转成：

```html
<figure><img src="..."><figcaption>说明</figcaption></figure>
```

正文图片由 `after_post_render` 处理，首页 Markdown 由 `home_content()` 处理。普通段落中的图片不动。

## 首页内容

`home_content()` 读取 `source/_data/home.md`，用 `hexo.render.renderSync` 渲染 Markdown，再做图注转换。结果按生成周期缓存。首页模板只负责布局，不保存介绍文本。

## 完整 HTML 画布

`canvas_document(content, base, bridge)` 做三件事：

1. 只接受包含 `<html ...>` 的完整文档；片段返回空字符串。
2. 在第一个 `<head>` 里插入 `<base href="...">`，让作品内的相对 CSS / JS / 图片解析到 `canvas_base`。
3. 在 `</body>` 前插入 `canvas-bridge.js` 脚本。

它不会重写作品自身的 `<title>`、字体、样式或脚本。外层页面的标题、作者、canonical 仍来自 front matter。

## 预设校验

`page_style(page)` 只接受：

```text
palette      rose tech wanderers sepia ink
typography   standard enhanced literary poem
```

未知值回退为空并只警告一次。笔记分类在未显式指定 `typography` 时自动使用 `enhanced`。

# 5. 分类与索引

## 目录即分类

`folder-categories.js` 在 `before_generate` 中：

1. 读取主题配置的 `sections`。
2. 把 `_posts/` 之后的目录逐级映射成分类名；未配置的目录直接用目录名。
3. 写入 `hexo.config.category_map`（分类名 → 目录名），供分类 URL 使用。
4. 对每个 Post 调用 `setCategories()`，覆盖 front matter 里的分类字段。

因此移动文件就会改变分类；permalink 不会随分类变化。

## 导航数据

`navigation-data.js` 提供：

- `publishedDocuments(site)`：已发布文章 + 独立内容页，排除 CSS/JS 等资源页。
- `recentlyUpdated(site)`：按 `updated || date` 倒序，同日按路径稳定排序。
- `miscPages(site, theme)`：没有归入 `sections` 分类的内容页。
- `nav_sections()`：`nav_primary`、分类（带文章数）、`nav_misc`（带数量）。
- `updated_pages()`：`/updates/` 使用的列表。

生成器：

| 生成器 | 输出 | 说明 |
| --- | --- | --- |
| `updates-index` | `/updates/` | 所有内容，按最近更新 |
| `category-index` | `/categories/`、`/categories/page/N/` | 分类卡片索引 |
| `tag-index` | `/tags/`、`/tags/page/N/` | 标签卡片索引 |
| `misc-index` | `/misc/` | 未归入导航分类的内容 |
| `nav-category-pages` | `/categories/<folder>/` | 配置了但暂时没有文章的栏目 |

分类地址由 `category_map` 与 `slugize` 生成；嵌套目录会形成 `/categories/notes/reading/` 这样的路径。

# 6. 统计

`site-stats.js` 的 `countWords(content)`：

1. 用 `htmlparser2` 解析正文。
2. 移除 `pre`、`code`、`script`、`style`、`.highlight`、`.note`。
3. 在块级元素边界插入空格，避免段落粘连。
4. 中日韩文字逐字计数，其他语言按词计数，支持无空格中英混排。

`page_stats()` 返回 `{words, minutes}`，阅读时间按 300 字/分钟向上取整，最少 1 分钟。

`site_stats()` 汇总已发布内容：页数、字数、分类数、标签数、平均篇幅、最长页面、栏目分布。结果在一轮生成内缓存。

`site_activity()` 生成近 365 天热力图：按站点时区归日，每页只取最近一次更新，向两侧补齐整周。它统计的是“最近更新时间”，不是历史修订次数。

# 7. 浏览器脚本

## navigation.js

只处理目录与信息窗两个 `details.hover-panel`：

- 宽屏普通页面（`min-width: 861px`）：两个面板常驻展开，`data-state="wide"`，不响应点击开合。
- 窄屏（`max-width: 860px`）或完整 HTML 画布：顶栏抽屉，点击开合、鼠标悬停展开、移出延迟 180ms 收起、点击固定。
- 抽屉互斥；遮罩随目录抽屉淡入淡出，信息抽屉不启用遮罩。
- Esc 关闭当前抽屉并把焦点还给开关；外部点击关闭。
- 动画从当前画面反向继续，退场结束才把 `details.open` 设为 `false`。
- `prefers-reduced-motion` 下直接切换状态。

`isCompact()` 在媒体查询命中，或页面是完整 HTML 画布（`data-canvas="document"`）时为真。Markdown 画布仍按宽度决定形态，宽屏保留常驻侧栏。

## reading.js

只在存在 `.post-info` 的页面加载：

- 阅读进度按真实滚动距离计算，底部 24px 内吸附到 100%，不可滚动时隐藏。
- 完整 HTML 画布：监听 iframe 的 `iris:canvas-progress`，同步进度与大纲高亮；点击大纲时向 iframe 发送 `iris:canvas-section`。
- 普通正文：滚动时更新大纲当前项。
- 首屏后的块加 `.reveal`，用 `IntersectionObserver` 逐段显现；减少动态效果时不隐藏。
- 信息窗的「信息 / 注释」页签，支持左右方向键。

## canvas-bridge.js

在完整 HTML 画布内部运行：

- `scroll` / `resize` / `load` 时用一帧节流上报。
- 计算 `scrollY / (scrollHeight - innerHeight)`，并把当前章节 id 一起发给父页。
- 收到父页的 `iris:canvas-section` 时滚动到对应 id。

## 外观实验室

`source/attachments/appearance/script.js` 只改 `body.dataset`（`layout`、`alignment`、`palette`、`typography`）、`meta[name=color-scheme]` 和预览输出，然后派发 `appearance:layout` 事件。导航脚本监听该事件并重新同步宽窄屏状态。

# 8. 样式与布局

## 加载顺序

```text
base → fonts → layout → navigation → pages → prose → info → presets
→ compact（max-width: 860px；完整 HTML 画布始终加载）
→ home（仅首页）
→ page.styles
```

- `base.css`：设计变量、reset、字体族、滚动条、减少动效。
- `layout.css`：三列 Grid、宽高上限、页眉页脚、画布两种形态。
- `navigation.css`：目录树、侧栏、抽屉、社交、画布外壳的中性配色。
- `pages.css`：标题圆点、文章列表、分类卡片、分页、首页概览。
- `prose.css`：正文排版、图注、诗歌块、逐段浮现。
- `info.css`：信息窗、页签、大纲、进度条。
- `presets.css`：五套配色与四套排版。
- `compact.css`：窄屏顶栏、抽屉、遮罩、单列布局；完整 HTML 画布固定使用这套顶栏。
- `attachments/home/home.css`：首页专用，不进入主题通用层。

## 宽度

```text
--reading-width   700px   article 纸张
--page-width      800px   page / canvas prose
--content-width  1000px   #main-content 上限
```

`body` 按布局设置 `--frame-width`，`.site-layout` 用三列：

```text
nav-width | minmax(0, 1fr) | nav-width
```

`page` 的 `centered` 对齐会去掉右列，只保留侧栏与正文。

## 画布两种形态

Markdown 画布：

```css
body[data-layout="canvas"] {
  --frame-width: var(--page-width);
}
```

- 内容页 800px，无纸张、无标题、无文章页脚。
- 侧栏、信息窗、站点页脚正常存在。
- 窄屏走 `compact.css`，宽屏走常驻侧栏。

完整 HTML 画布：

```css
body[data-layout="canvas"][data-canvas="document"] {
  --frame-width: 100%;
}
```

- 顶栏固定在视口顶部；`.site-layout` 从顶栏下缘开始，高度为 `100dvh - --top-nav-height` 的纵向 flex。
- `#main-content` `flex: 1`，`.content-page` 绝对定位铺满。
- iframe 宽高 100%，去掉边框与圆角。
- 站点页脚留在最后，占一行高度。
- 目录与信息窗是顶栏两侧的固定触发器，打开后是抽屉；画布本身始终铺满剩余空间。

## 画布侧栏修复

旧规则把 `backdrop-filter` 加在 `.site-menu` 上：

```css
[data-layout="canvas"] :is(.top-nav, .site-menu, .site-menu-body, .post-info-body) {
  backdrop-filter: blur(28px) saturate(0%);
}
```

`backdrop-filter` 会让元素成为 `position: fixed` 后代的包含块。窄屏时 `.site-menu` 只有 40px 宽，抽屉 `.site-menu-body` 的 `width: min(320px, 100%)` 就按 40px 计算，退场位移也只移动 40px，看起来像一条竖排窄条。

修复方式是只给真正需要玻璃效果的容器加滤镜，不再给 40px 触发器 `.site-menu` 加：

```css
[data-layout="canvas"] :is(.top-nav, .site-menu-body, .post-info-body) {
  backdrop-filter: blur(28px) saturate(0%);
}
```

同时 `compact.css` 对普通页面只在 `max-width: 860px` 加载，Markdown 画布因此能在宽屏恢复常驻侧栏；完整 HTML 画布为了保留顶栏而始终加载它，并把 `isCompact()` 视为真。

## 滚动条

`base.css` 对非 `page` 布局隐藏根滚动条，用进度条替代文章阅读进度；其余滚动条统一使用主题色。`page` 保留系统滚动条，因为列表页需要明确的滚动位置。

# 10. 修改指南

## 新增一个布局

1. 在 `page_layout()` 的允许列表里加名字。
2. 在 `layout/` 加薄封装，复用 `content-page`。
3. 在 `layout.ejs` 决定标题、信息窗、页脚与 CSS 条件。
4. 在 `layout.css` 或对应职责的 CSS 里加状态规则。
5. 补 `build-integration` 的页面断言。

## 新增 helper 或生成器

- helper 放在 `scripts/` 的职责文件里，通过 `hexo.extend.helper.register`。
- 生成器放在 `navigation-data.js`，返回 `{path, layout, data}` 或数组。
- 需要跨次生成缓存时，在 `before_generate` 清空。
- 涉及 `site.pages` 时先用 `lib/documents.js` 过滤掉 CSS/JS 资源页。

## 新增单页资源

放到 `source/attachments/<slug>/`，不要放回 `themes/iris-paper/source/css/`。主题通用样式只放会跨页面复用的规则。

## 修改断点

同步三处：

1. `layout.ejs` 的 `compact.css` media。
2. `navigation.js` 的 `matchMedia('(max-width: 860px)')`。
3. `compact.css` 的布局规则与相关测试。

## 注释约定

- JS / CSS / EJS 不写解释性注释。
- 页面 HTML 可以在分块处保留目录性质的注释，如「导航元素」「主内容区域」。
- 复杂算式如果必须说明，优先写进本文档，而不是散落在代码里。
- 不为了“以后可能用到”保留死代码或兼容层。
