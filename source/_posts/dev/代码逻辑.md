从一个源文件到完整页面，主要经过分类处理、内容索引、EJS 外壳和浏览器交互四层。日常用法与配置示例见[参考速查](/reference/)，真实外观可在[外观实验室](/appearance-lab/)查看。

# 从源文件到页面

1. Hexo 读取 `source/` 和 front matter，渲染 Markdown / HTML。
2. `after_post_render` 把独占段落且带 title 的图片转为 figure 与图注。
3. `before_generate` 按目录重设文章分类，并清空本轮正文、首页与统计缓存。
4. 生成器产出索引页、分类页和 `search.json`。
5. EJS 取导航、统计、注释与正文，组装页面。
6. 主题 `source/` 的 CSS、JS、字体，以及站点附件目录复制到 `public/`。

构建脚本集中在 `themes/iris-paper/scripts/`：

每个文件注册一件事，文件名即职责：

| 文件 | 注册内容 | 职责 |
| --- | --- | --- |
| `folder-categories.js` | `before_generate` | 目录到分类链、分类英文网址映射 |
| `content-notes.js` | `split_note` | 顶层 `div.note` 拆分与生成周期缓存 |
| `content-figures.js` | `figures`、`after_post_render` | 独占段落带 title 的图片转 figure |
| `home-content.js` | `home_content` | 读取并渲染 `_data/home.md` |
| `page-style.js` | `page_style` | palette 与 typography 校验 |
| `page-layout.js` | `page_layout` | article / canvas / page 判定 |
| `canvas.js` | `canvas_document` | 完整 HTML 画布的 base 与桥接注入 |
| `content-warning.js` | `content_warning` | 成人标签判定、自定义警告块拆分 |
| `navigation-data.js` | `nav_sections` 等 | 菜单、最近更新、其他页面、分类和标签索引、空栏目页 |
| `search-index.js` | `search-index` | 公开内容的标题、标签与纯文本搜索索引 |
| `site-stats.js` | `page_stats`、`site_stats`、`site_activity` | 字数、阅读时间、全站统计与更新热力图 |

三个共享模块放在 `scripts/lib/`：

| 文件 | 职责 |
| --- | --- |
| `documents.js` | 已发布文章与独立内容页的共同筛选规则 |
| `html-text.js` | 从渲染后 HTML 取纯文本的共同流程 |
| `content-warning.js` | 警告块识别与拆分，供构建与统计共用 |
| `figure-captions.js` | 图注转换的实现 |

`publishedDocuments(site)` 合并已发布文章和独立内容页；`standalonePages(site)` 排除 CSS/JS 等有文件扩展名的资源，保留 HTML 页和目录式内容页。最近更新、搜索与统计共用这层筛选，不分别维护内容范围。

`htmlText(content, exclude)` 统一解析、移除节点、在块边界补空格、取文本四步，**排除规则由调用方传入**而不是写在共享函数里：搜索排除 head、script、style、template、noscript 和警告块；统计排除 pre、code、script、style、`figure.highlight`、`div.note` 和警告块。两套排除集合差异明显，共享的只是流程。统计不受块级正则里 `pre` 的影响，因为 `pre` 在排除阶段已整体移除。

# 分类归属与菜单显示分开

`folder-categories.js` 在 `before_generate` 中读取所有 `sections`：

- 逐级把 `_posts/` 后的目录名映射为 label，未配置的目录保留原名。
- 调用 Post 的 `setCategories()`，覆盖 front matter 的分类字段。
- 建立 `category_map`，让 label 对应英文 folder 地址；嵌套目录形成分类链。

`navigation-data.js` 的 `nav_sections()` 返回三个分组：

- primary：按 `nav_primary` 顺序输出固定链接，模板用两列 Grid 展示。
- categories：按 `sections` 顺序输出分类、图标与篇数，先过滤 `nav === false`。
- misc：按 `nav_misc` 输出链接和数量。

`nav` 只控制菜单，不能用于过滤目录映射、分类索引、统计或 misc 的归属判断。`miscPages()` 继续用全部已配置分类的 label 判断，因此隐藏菜单的分类不会被误收进「其他页面」。省略 nav 的既有配置保持显示。

生成页面：

| 输出 | 来源与规则 |
| --- | --- |
| `/updates/` | 全部内容按 `updated || date` 倒序，同时间按路径排序 |
| `/archives/` | Hexo 默认文章归档，按发布日期 |
| `/categories/`、`/tags/` | 非空分类 / 标签卡片；taxonomy_per_page 控制索引分页 |
| `/categories/<folder>/` | 默认分类生成器；配置了但没有文章的栏目由主题补空页 |
| `/misc/` | 未归入任何 sections 分类的内容页 |
| `/search.json` | 全部已发布内容，不含自动生成的索引页 |

隐藏菜单项仍保留空分类页生成行为。`taxonomy_preview` 只控制卡片预览篇数，不限制分类列表或搜索内容。

# 页面外壳与正文

`page_layout(page)` 将 article、canvas 以外的布局统一视为 page。`layout.ejs` 据此决定信息窗，并通过正文是否包含 `<html ...>` 判断完整 HTML 画布。

```text
layout.ejs
├─ head：模式初始化、字体、通用 CSS、页面 styles、延迟脚本
├─ header：站点标识、窄屏顶栏、阅读进度
├─ site-layout
│  ├─ site-rail
│  │  └─ site-menu
│  │     ├─ site-tools-slot：宽屏工具插槽
│  │     ├─ navigation：双列索引 + 分类列表
│  │     ├─ site-stats
│  │     └─ social-links：一道分割线，紧贴统计
│  ├─ main → article / page / canvas → content-page
│  ├─ post-info：article 与 canvas 的统计、元数据、注释、大纲
│  └─ site-footer
├─ menu-backdrop
└─ search：全站唯一的原生 dialog
```

三种内容模板复用 `_partial/content-page.ejs`，标题用 `page-title`，正文用 `post-content`。article 使用 700px 纸张，page 与 Markdown canvas 使用 800px 框架，宽度由 `--frame-width` 单独决定；main 不再另设 1000px 上限，因为 grid 主列已被 `--frame-width` 约束，而完整文档画布另有 `max-width: none` 覆盖，那条上限在所有组合下都不生效。page 的 centered 对齐去掉右侧空列，balanced 保持三列平衡。

`layout.ejs` 顶部先算出 `bodyAttributes` 数组再输出到 body 标签，避免把六个条件属性拼成一行。`content_warning(page)` 在 layout 顶部求值一次，供脚本加载判断与信息窗复用；内层 `page.ejs` 另求值一次——Hexo 先渲染内层模板再渲染外层 layout，两者无法共享局部变量，而 helper 内部按内容缓存，重复调用是查表而非重新解析。

`body.dataset` 描述作者的页面设置：layout、alignment、palette、typography；canvas 另有 canvas=document 或 prose。浏览器模式单独写在根 html 的 `data-mode-preference` 与 `data-mode`，不覆盖作者 palette。

## 正文、图注与注释

`figureCaptions()` 处理独占段落且带 title 的图片，保留 alt，把 title 移入 figcaption。首页内容从 `source/_data/home.md` 读取，同样做图注转换。

`splitNote()` 使用 htmlparser2 的源字符位置拆出顶层 `div.note`，保留块内原始 HTML；嵌套 note 只计算一次，多个块按顺序合并。普通正文显示去掉注释后的 body，信息窗按是否有注释决定页签。解析结果按一轮生成缓存，下一轮清空。Markdown 内的 `div.note` 开闭标签与内容需用空行分隔，让 Markdown 渲染器先生成链接与强调；拆分器只搬运 HTML，不重新解释 Markdown。

`page_style()` 校验五种 palette（rose、tech、wanderers、sepia、ink）和四种 typography（standard、enhanced、literary、poem）。未知值返回空值并仅警告一次。笔记在未显式指定 typography 时使用 enhanced。

## 成人内容警告

`content_warning(page)` 精确匹配 `成人内容` 标签，支持 Post 的标签关系和独立页的标签数组，返回 enabled、去掉 `div.content-warning` 的 body 与自定义 message。拆分器使用 htmlparser2 的源字符位置保留原始 HTML，多个外层块顺序合并，嵌套块只提取一次；结果按生成周期缓存。警告块是保留的元数据块，无标签时也不作为正文输出；搜索和字数统计排除它，大纲使用清理后的正文。

`_partial/content-page.ejs` 为启用警告的页面增加 `is-content-locked`，在保护内容外包裹 `.content-warning-body`，警告层作为它的兄弟节点，只覆盖内容容器。默认文案与继续阅读链接集中在 `_partial/content-warning.ejs`，仅保留「内容警告」标题；`content-warning.css` 将内容置于顶部、水平居中，链接与正文共用 prose.css 的样式，随主题配色变化。

**遮罩是渐进增强的，不依赖 JavaScript。** 模板不输出静态的 inert 与 aria-hidden，由 `content-warning.js` 在初始化时调用 `lock()` 添加——否则没有脚本时这两个属性永远摘不掉，正文会连同遮罩一起变得不可读。两条路径分别是：

- 有 JS：初始化即加锁，点击「继续阅读」阻止锚点跳转、移除布局锁定，以 Web Animations 同时淡出遮罩、显现正文。时长复用 motion-base（250ms）和 motion-reveal（500ms）。动画结束后隐藏遮罩、恢复正文交互与辅助阅读，焦点移入正文并恢复原有锚点；重复点击不重启动画。
- 无 JS：`:root:not(.js)` 下由 `#content-warning-body:target` 显示正文，`:has()` 同时收起遮罩。「继续阅读」本身就是指向正文的锚点链接，所以不需要脚本参与。

继续阅读链接不再按 `.js` 门控显隐。无 JS 时隐藏它会让带标签的页面正文完全不可达，那是内容丢失而不是保护。

`content:continue` 通知阅读脚本重新计算进度与大纲，逐段浮现延迟至首次确认后初始化。pagehide 和历史缓存 pageshow 取消未完成的动画并重新锁定，旧动画不会解除新遮罩。确认状态不写入 localStorage 或 sessionStorage：每次进入都要重新确认。

## 完整 HTML 画布

`canvas_document()` 为完整文档在 head 注入素材 base，在 body 结束前注入 `canvas-bridge.js`，放入 sandbox iframe。作品保留自己的 title、CSS、JS 和配色；外层元数据仍来自 front matter。

sandbox 允许脚本、弹窗、下载和用户触发的顶层跳转，不包含 allow-same-origin。父页与作品通过 postMessage 通信：

- iframe → 父页：`iris:canvas-progress`，携带 progress 与 section。
- 父页 → iframe：`iris:canvas-section`，携带要跳转的章节 id。

父页校验消息来源为当前 iframe。完整画布始终使用顶栏与抽屉；宽屏 iframe 铺满顶栏与紧凑页脚之间，窄屏隐藏页脚并铺满顶栏以下视窗。Markdown canvas 仍按屏幕宽度选择侧栏或抽屉，页脚不变。

# 搜索：构建索引，浏览器本地匹配

`search-index.js` 注册生成器，为每个已发布内容输出：

```text
{title, url, tags, text}
```

url 使用 Hexo 的 url_for，遵循站点 root 与 pretty_urls，支持子路径部署。`searchText()` 解析已渲染 HTML，移除 head、script、style、template、noscript，在块边界加入空格，解码实体并合并空白。完整 HTML 画布与普通文章走同一路径；正文不截断。

`site-tools.js` 第一次打开搜索才加载索引，并复用正在进行的请求和成功结果。失败后显示重新加载按钮。请求完成时读取最新输入，不展示旧查询结果。

匹配规则：NFKC 统一全半角，忽略大小写，按空白拆词；所有词都必须在标题、标签或正文中出现。每个词的标题命中计 10 分、标签 5 分、正文 1 分，按总分排序，同分按 URL 排序。结果显示正文中的首个关键词附近片段；标题和片段通过 textContent 写入，不执行文章中的 HTML。

**归一化只在索引加载后做一次。** 索引到手时就为每条文档缓存好归一化的标题、标签、正文和三者拼接串，之后每次按键只归一化查询词再做 `includes` 比较。此前每个 input 事件都要对全站每篇正文重跑一遍 NFKC，文章越多越卡；实测同一组查询的平均单次耗时从 0.32ms 降到 0.03ms，而站内只有 11 篇内容，差距随内容量放大。摘要定位复用同一份缓存，不再二次归一化正文。

原生 dialog 提供模态焦点约束和 Esc 关闭；关闭按钮、弹窗外点击也可退出，关闭后焦点回到工具按钮。打开搜索派发 `site:search`，由导航脚本关闭窄屏抽屉。`Ctrl / ⌘ K` 调用同一入口。

# 模式：偏好与实际配色分开

`theme.js` 在 head 中同步加载，先于样式读取 localStorage 的 `iris-mode`，避免页面先亮后暗：

- `data-mode-preference` 是 system、light、dark，默认 system。
- `data-mode` 是解析后的 light 或 dark。
- system 通过 prefers-color-scheme 决定实际模式，并监听实时变化。
- light / dark 不受系统变化影响。

`window.irisTheme.setPreference()` 更新模式并保存选择；storage 事件同步同源标签页，删除偏好回到 system。读写存储失败时仍更新当前页。实际模式同时更新根 color-scheme 与 meta，再派发 `theme:change`。

`site-tools.js` 用当前偏好更新图标、标签与下一次点击目标：system 为 brightness_auto，light 为 light_mode，dark 为 dark_mode；点击按 system → light → dark 循环。这里不用二态的 aria-pressed 表达三态，完整状态放在按钮可访问名称与 title。

深色规则复用 presets 的 ink 色值，对根与 body 一起覆盖。日间保留页面原有亮色 palette；当作者指定 ink 时回到默认亮色。默认亮色 token 只在 base.css 声明一次，由一组选择器共用，不在 tools.css 另抄一份——两份同样的色值早晚会改出分歧。画布外壳仍使用中性色，作品 iframe 内部不受影响。

深色选择器写成 `:root[data-mode="dark"]:root` 是为了压过 palette 覆盖，不是冗余。`:root:has(body[data-palette="tech"])` 的优先级是 (0,2,1)，`:has()` 取最具体参数再叠加 `:root`；而朴素的 `:root[data-mode="dark"]` 只有 (0,2,0)，即使写在后面也会输。tech、sepia、wanderers 三套配色都有这个形状，夜间模式下根层颜色会停在亮色。重复 `:root` 把优先级提到 (0,3,0) 后三者都正常，`colors.test.js` 对每套配色的夜间取色都有回归断言。

外观实验室通过 `appearance:layout` 更新页面状态；工具脚本调用 `previewPalette()` 临时展示配色，不写入偏好。布局变更后导航重新同步工具插槽和面板形态。

# 导航与阅读交互

## 同一组工具随布局移动

`navigation.js` 的 `syncLayout()` 将唯一的 `.site-tools` 移动到对应插槽：宽屏放在 `#site-tools-slot`，居中显示，并与下方索引入口以一道分割线分隔；窄屏或完整 HTML 画布放进 `.top-nav`，在信息按钮左边。page 没有信息窗时，顶栏不为它预留空位。顶栏标识使用具名容器查询：标识可用宽度达到 230px 时显示签名，更窄时只显示可截断的站名。目录、信息、搜索和模式按钮共用 52% 强调色的默认态，以及完整强调色的悬停、焦点和触发态；搜索通过 aria-expanded 同步展开状态。

移动的是同一组节点，保留事件和焦点能力，不创建两套搜索或模式状态。断点为 max-width: 860px；完整 HTML 画布无视宽度，始终是 compact。

## 抽屉状态机

目录和信息窗是普通容器 `div.hover-panel`，触发器是独立的 `button.panel-toggle`，面板内容是 `.panel-body`，两者通过 `aria-controls` 关联：侧栏为 `#mobile-nav` 控制 `#site-menu-content`，信息窗为 `#post-info-toggle` 控制 `#post-info-content`。

这里**不用 `<details>` + 隐藏 `summary>`**。宽屏下把 summary 设为 `display:none` 再用脚本强制 open，语义上仍是一个折叠组件，而它的触发器被藏了：辅助技术会播报一个可展开控件，用户却永远无法与之交互；无 JS 宽屏更是无从消除这层语义。靠 role 去覆盖原生 disclosure 语义在各浏览器与辅助技术上并不可靠，那是把问题藏起来而非修掉。

- 宽屏：触发器 `display:none` 并移除 `aria-expanded`（隐藏按钮的状态对辅助技术没有意义），面板常显、不 inert，状态 wide。
- compact：点击开合；鼠标悬停展开，移出后延迟 180ms 收起；点击可固定展开。`hidden`、`inert`、`aria-hidden`、`aria-expanded` 同步变化。
- 两个抽屉互斥；只有目录启用遮罩。信息窗面板限高 calc(75dvh - 顶栏高度)，与顶栏合计最多占可见视窗的 75%，下方保留 25%，内部滚动；目录限宽 min(320px, 75vw)，高度铺满顶栏以下。
- Esc 关闭并还原焦点，外部点击关闭。收起时若焦点还在面板内，先把焦点移回触发器再设 inert，避免焦点落在 inert 子树里。
- 动画可以从当前帧反向：进场前先解除 `hidden`，退场**结束后**才重新 `hidden`，并挂在与 WAAPI 相同的 finish 分支上，让快速连续开关不会留下「可见但已标记 hidden」的错位。减少动态效果时立即切换。

无 JS 时 compact 下面板直接展开可达，触发器隐藏。侧栏与信息窗用 `order` 排到正文之后，否则用户一进页面先看到的是整棵导航树而不是文章。完整 HTML 画布另解除 `overflow: hidden` 与固定高度，否则后置的导航会被不可滚动的视口挡住。取舍是明确的：无 JS 时不提供折叠交互，只保证内容与导航都可达——一个点不动的折叠控件比没有折叠更糟。

不要给 40px 宽的固定触发器增加 transform 或 backdrop-filter：它们会改变后代 fixed 抽屉的包含块，让抽屉缩成窄条。滤镜只加在顶栏和实际面板 body。

## 阅读脚本

`reading.js` 只在 article / canvas 加载：进度按真实滚动范围计算，底部 24px 内吸附 100%，无滚动时隐藏；同一进度同时写入顶栏与信息窗。宽屏信息窗、内容滚动区和进度条裁切层显式使用同一个 nav-radius，填充条不另设圆角，贴合面板顶边。大纲高亮按标题位置更新，完整画布改为读取 iframe 消息。信息 / 注释页签支持左右键。普通正文通过 IntersectionObserver 逐段浮现，首屏直接显示，减少动效时不隐藏。

## 动画口径

| 动画 | 参数 | 理由 |
| --- | --- | --- |
| `page-enter`（页面标题） | 150ms，透明度 0.9 → 1，无位移 | 每次导航必见、且发生在读者最想立刻看到内容的瞬间，因此只保留一层极轻的淡入，不再对每个顶层区块逐一播放，也不再用 `backwards` 让首屏内容等动画才可见 |
| `.info-page`（信息 / 注释页签） | 250ms，复用同一组关键帧 | 切页签是低频的主动操作，稍明显的淡入是状态反馈。`hidden` 变为可见会重新启动 CSS 动画，所以这条复用确实生效 |
| `reveal`（正文逐段浮现） | 500ms，只过渡透明度 | 首次进入视口的解释性动画，不是反复触发的交互，500ms 合于纸张感的气质；原先叠加的 14px 位移在长文里会累计几十次、滚动时发晃，已去掉 |

正文区块不再挂 `will-change`。它原本在 `is-done` 分支收回，但首屏那批直接标记 `is-visible, is-done`、从未经历过 transition，挂了又立刻收回；而 transition 一旦被打断、`transitionend` 不触发，`is-done` 就永远加不上，`will-change` 会长期占用合成层。

`base.css` 在 `prefers-reduced-motion: reduce` 下统一关闭 animation 与 transition，`reveal` 另有 `no-preference` 门控，两层不冲突：前者是兜底，后者保证减少动效时正文**不会**先被设成透明。

# 统计口径

`countWords()` 排除代码、脚本、样式、highlight 和 note，中日韩文字逐字计数，其他语言按词计数。阅读时间按每分钟 300 字向上取整，单页最少 1 分钟。全站统计按生成周期缓存，内容改变后的下一轮会重算。

更新热力图覆盖近 365 天，按站点时区把每页最近一次更新归到日期，不代表历史修改次数。栏目分布使用所有 sections，包括隐藏菜单的分类，同一页面可计入多个分类。

# 样式、资源与图标

加载顺序：

```text
base → fonts → layout → navigation → pages → prose → info → presets → tools → content-warning
→ compact（max-width: 860px；完整 HTML 画布始终加载）
→ attachments/home/home.css（仅首页）
→ page.styles
```

base 放设计变量、默认亮色 token 和基础规则；layout 放骨架；navigation 放菜单、社交与画布外壳中性色；pages 放标题、列表和卡片；prose 放正文；info 放信息窗；presets 放作者配色与排版；tools 只放工具与搜索，不放配色；content-warning 放内容遮罩与继续阅读链接的布局；compact 负责顶栏、单列、抽屉与无 JS 的单列顺序。

token 的去留有两条规矩。颜色只在一处声明，由选择器列表共享，不在第二个文件重抄。没有任何 `var()` 引用的 token 直接删掉，不留着「以后可能用」——`--content-width` 和 `--secondary` 就是这样消失的，后者还在四套配色里各重复定义过一遍。

链接末尾的箭头由 `.section-more`、`.taxonomy-more` 的伪元素绘制，不写进链接文本。伪元素不进无障碍树，屏幕阅读器不会把它念成奇怪的东西，间距也能用 token 控制而不是靠一个裸空格。

单页资源放在 `source/attachments/<页面名>/`。外观实验室位于 `source/_posts/dev/外观实验室.md`，资源在 `attachments/appearance-lab/`，网址为 `/appearance-lab/`。控件保留原生 select 的选择行为，以 appearance: none 去掉浏览器默认箭头；label 伪元素统一绘制箭头，右侧预留 36px，避免箭头贴边或遮住文本。

图标使用自托管 Material Symbols Rounded 子集。新增图标不只是增加连字名，还要更新 `MaterialSymbolsRounded.woff2`，否则会把图标名称裁成字母。当前子集包含分类、目录、信息、注释、搜索、关闭，以及昼/夜/系统三个模式图标。使用 Google Fonts CSS API 的 icon_names 参数获取子集时，保留全部既有名称，并使用现代浏览器 User-Agent 获取 WOFF2 变量字体。正文的字体分块由 `tools/build-fonts.py` 管理，不用于重建图标字体。四个社交图标统一在主题 `source/icons/` 本地托管，通过同一套 CSS 遮罩与 currentColor 着色，继承链接的正常色、悬停强调色和键盘焦点色。GitHub、X 的既有路径移到独立 SVG，避免逐页重复内联数据，并可跨页面使用浏览器缓存；SCP 保留原 PNG，以亮度遮罩保留环线与箭头，Bangumi 保留原 SVG。

# 修改与验收

```bash
npm run test:theme
npm run build
```

测试位于 `themes/iris-paper/test/`，共 106 例：真实 Hexo 临时站点构建覆盖分类、分页、布局、社交、搜索产物，以及五种布局下的面板结构；navigation 覆盖抽屉状态机、`hidden` / `inert` / `aria-expanded` 同步、快速反向与宽屏折叠语义的移除；site-tools 覆盖三态模式、系统变化、跨标签同步、搜索归一化次数与重试；content-warning 同时覆盖有 JS 的确认流程和**不执行脚本**时正文可达；html-text 覆盖排除规则由调用方指定。其余测试覆盖正文处理、阅读、统计、颜色与模板规则。

JSDOM 测试给浏览器内建原型打 spy 时，要用被测窗口的原型（`window.String.prototype`）而不是 Node 自己的——两者是不同 realm，挂错了 spy 永远记录不到调用，看起来像实现坏了。

新增内容范围时先更新 `lib/documents.js`，再检查搜索、统计和最近更新是否一致。新增分类可见性规则只改导航筛选，不改变分类归属。改断点时同步 layout.ejs 的 media、navigation.js 的 matchMedia 与 compact 布局。

依赖只保留实际被引用的。`hexo-theme-landscape`、`hexo-renderer-stylus`、`hexo-browsersync` 在仓库里零引用，已连同 144 个传递依赖移除；`hexo-renderer-marked` 必须留着，Markdown 渲染靠它，尽管没有文件字面提到它。npm 报告的几个 low severity 构建期告警不做 `audit fix`：产物是纯静态文件，为此引入版本漂移不值得。

验收还要在浏览器检查：宽屏工具居中、窄屏顺序、搜索焦点与 Esc、三种模式图标、系统外观实时变化、社交分割线与紧贴位置，以及完整画布外壳。图标字体需要看实际渲染，不能只断言连字名称正确。

纯重构应当拿产物说话：改动前后各跑一次 `npm run clean && npm run build`，用 `diff -r` 比对 `public/`，并单独比对 `search.json`。对比前要消除重建噪声——同步源文件 mtime、复用原 `db.json`，否则归档出的新 mtime 会改掉页面上的时间，同日文章也会因载入顺序不同而换位。

两类浏览器验收容易出假结论。一是 headless Chrome 的 `--window-size` 不保证生效，截图可能按别的宽度渲染出不存在的溢出；要用 CDP 的 `Emulation.setDeviceMetricsOverride` 强制视口，并以 `scrollWidth` 对比 `clientWidth` 判断是否真的横向溢出。二是预览服务中途退出后，页面仍能打开却加载不到 CSS，看起来像样式全丢；先确认 `/css/*.css` 返回 200 再下结论。

代码文件不添加解释性注释；页面 HTML 可保留分块目录注释。机制与约定在本文集中维护，日常操作留在参考速查。
